Dashtro turns `.sql` files and Markdown or Astro pages into dashboards. You write
the query, you run the query, and a chart renders the rows.

<CardGrid stagger>
	<Card title="SQL-first" icon="approve-check">
		Import a `.sql` file as a module and call `run()`. Dashtro binds the
		parameters and returns plain rows.
	</Card>
	<Card title="Presentational charts" icon="puzzle">
		Charts render the rows you pass. They never fetch, so they work in
		static builds, SSR pages and client islands alike.
	</Card>
	<Card title="Built-in filters" icon="setting">
		Add a select, a date range or a number slider with one `filters` prop.
	</Card>
	<Card title="DuckDB and Postgres" icon="laptop">
		One connection string. Dashtro rewrites `:name` placeholders for each
		dialect.
	</Card>
</CardGrid>

## Charts from your SQL

These charts pass `data` directly, so they need no database. In a real dashboard
you run `sql.run()` in the page and pass the rows the same way.

<section class="not-content dashtro-example dashtro-chart-grid">

    client:load
    data={monthly}
    x="month"
    series={[{ key: 'desktop', label: 'Desktop' }, { key: 'mobile', label: 'Mobile' }]}

## How these docs are organised

The pages follow the [Diátaxis](https://diataxis.fr/) structure:

- **Tutorials** teach you by building something. Start here if Dashtro is new.
- **How-to guides** solve one specific problem. Look here when you know the goal.
- **Reference** describes the exact API. Look here for options and types.
- **Explanation** discusses why Dashtro works the way it does.

If you want to see a full app first, the package ships an
[example](https://forgejo.pm4.uk/peter/dashtro/tree/main/example) with two
dashboards over real data. The source lives on
[Forgejo](https://forgejo.pm4.uk/peter/dashtro).
